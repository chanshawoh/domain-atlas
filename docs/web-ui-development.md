# Web UI 首版实现

日期：2026-09-10。

## 设计与技术栈

设计源：[DomainAtlas Web UI Design Use OPUS](https://www.figma.com/make/iCmhwCV3ZDL26NeEir4302/DomainAtlas-Web-UI-Design-Use-OPUS)。

已调用 Figma `get_design_context`；Make 返回的源码资源在当前连接器读取时出现 `Unknown resource`，因此使用浏览器中的实际预览核对布局、配色、组件与交互。保留 56px 顶部栏、200px 左栏、360px 桌面详情栏、浅色点阵地图与分域能力卡片。品牌 SVG 来自预览 DOM 中的原始矢量，导出时补充 XML namespace 与明确的蓝色色值；没有重新绘制其几何图形。其余图标沿用设计所用的 Lucide。

参考 JourneyStage 当前包配置，使用 React 19 / TypeScript / Vite 7 / Tailwind 4 / Lucide，以及 Fastify 5 + 静态文件服务。DomainAtlas 保留原有 `src/` CLI 核心，仅增加 `apps/web` 工作区和 `src/web` 查询与服务模块；没有整体迁移为 JourneyStage 的多包结构。

## 运行

```sh
pnpm install
pnpm build
pnpm ui
# http://127.0.0.1:4310

# 自定义端口
pnpm ui --port 4311
```

前端热更新：保留默认端口的 `pnpm ui`，在另一终端执行 `pnpm dev:web`，打开 Vite 显示的地址。`/api` 代理到 `127.0.0.1:4310`。修改服务端后执行 `pnpm build:core` 并重启 `pnpm ui`。

查看其他项目：在其 Git 根目录运行 `node /绝对路径/DomainAtlas/dist/src/cli.js ui`。Web 查询不会自动初始化 `.domainatlas`。

## 已实现范围

- 读取真实域、能力和变更记录，统计总数与 Git 提交状态；没有将 Commerce 示例数据写入项目。
- 业务地图与列表、名称搜索、能力置信度筛选、缩放、域/能力详情及来源证据。找不到所属域的能力仍可见，并明确提示。
- 最近记录、全量记录页、关键词/日期/类型/状态筛选、能力过滤和列表分页。
- 变更详情中的原始需求、完整摘要、文件版本、结构化测试结果、能力来源、任务 ID、Git SHA、原始 JSON 与复制记录 ID。
- 纠正/撤销关联到原记录，原记录也显示后续关联；历史不会被重写。
- 加载中、未初始化、无记录、筛选无结果、事实格式错误、Git 读取失败分别展示；空测试数组显示“未采集”。
- 桌面并排详情；窄屏使用可关闭侧面板，首次加载不自动覆盖地图。系统字体回退，不要求外部字体网络请求。

## 查询与安全边界

`GET /api/atlas` 每次从事实 JSON 重建内存投影，校验字段、ID/文件名和普通文件类型，并通过现有 `GitObserver` 解析 Git 状态。`GET /api/changes/:id` 仅按已加载记录 ID 匹配，不接受磁盘路径。API 只读，仅监听 IPv4 loopback，校验本地 Host/Origin，不开放跨域读取或写接口。

首版面向单个本地项目：一次返回完整事实集合，搜索与分页在浏览器中完成；刷新会逐条查询 Git，尚未针对大型记录库优化，不提供服务端分页、后台缓存或自动轮询。复制记录 ID 失败时有手动复制提示。Markdown 原始需求/摘要以纯文本保留，不执行其中 HTML 或脚本；列表标题提取首个非空行，详情保留完整内容。

“已提交”沿用已有 Git 观察器的首次包含记录语义。没有新增推送、部署、业务验收、当前有效业务状态重算、测试自动采集、数据库或 MCP 传输能力。
