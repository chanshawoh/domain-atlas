# 身份与需求来源

DomainAtlas 分别记录开发环境身份、Git 作者、Git 提交者、需求提出者和反馈方。环境身份和需求来源写入新的不可变记录；提交信息从 Git 历史投影，使用 `pnpm domainatlas list` 或 Web 详情查看。

| 信息 | 字段 | 采集依据 |
| --- | --- | --- |
| 开发环境身份 | `attribution.developmentIdentity` | Hook 在任务开始时读取当前项目有效的 `git config user.name/user.email`，保存采集时间和 `capturePoint: turn-start`；手动录入时为 `ingest` |
| 需求提出者 | `attribution.requestedBy[]` | 从本轮用户原文中的明确提出需求句式提取 |
| 反馈方 | `attribution.feedbackBy[]` | 从本轮用户原文中的明确反馈、反映、报告句式提取 |
| Git 作者 | `lifecycle.author` | 事实记录首次进入 Git 历史的 commit 的 author 姓名、邮箱 |
| Git 提交者 | `lifecycle.committer` | 同一 commit 的 committer 姓名、邮箱 |

## 示例

开发环境的 Git 配置为 `woody`，输入：

> clp 提了需求，前端反馈订单列表缺少手机号，请帮我修改。

新记录会保存开发环境身份 `woody`，需求提出者 `clp`（称呼），反馈方 `前端`（角色）。双方分别带有 `source: request`、原话 `evidence` 和 `confidence: medium`。之后即使更换 Git 配置或由其他人提交，开发时保存的身份也不变，真实提交中的作者和提交者分别显示。

也支持“clp 提过来手机号查询需求”“这个需求是 clp 提过来的”“前端提过来某某需求”“支付团队反馈退款失败”等明确表述。多个明确来源分别保存，同一类中的重复称呼去重；同一个称呼可以同时是提出者和反馈方。

## 识别与历史边界

- 来源提取使用有限中文句式规则，属于待核对的中置信度信息，不是通用自然语言理解或人员身份认证。`clp` 保留为称呼，“前端”保留为角色，“支付团队”保留为团队，不猜测真实姓名或账号映射。
- 仅解释本轮用户输入，不从助手总结或前几轮补全来源。疑问、否定、假设、示例、代码块等受支持的排除句式不直接认定为来源；未匹配的复杂表达仍保留在完整 `request` 中。建议直接写“clp 提了某某需求，前端反馈某某问题”。
- Git 配置缺失时记录 `null`；部分配置只保存已有值。不使用操作系统用户名补齐，不把开发环境身份视为实际代码作者。
- 待提交记录没有 Git 作者/提交者。提交后读取的是**包含事实记录的提交**，不证明所有变更文件由该人编写，也不回绑到任务中更早发生的代码提交。
- 旧记录保持原样，不用今天的 Git 配置或新提取规则回填。Web 显示“未采集”；升级前已经开始、没有身份快照的任务也保持未知。旧记录已有的 Git 提交仍可展示作者与提交者。
- Web 详情分别展示上述信息及原话依据；变更记录搜索可匹配需求、摘要、记录 ID、来源称呼和 Git 姓名/邮箱。纠正历史事实继续使用追加的 `correction` 记录，不覆盖原记录。

构建 `pnpm build` 后，现有 Hook 和 `ingest-codex` 自动使用这些字段。此功能本身不提交或推送 Git，也不改写用户的 Git 配置。
